# 分阶段实施与放行

以下是将来的验收计划，**没有在本轮运行这些功能测试**。本轮只检查设计资料、源码依据与 Canvas 渲染。

## 阶段 1：先统一读模型

新增领域项目/组件身份、旧模型读取适配、只读列表投影和共用详情。先复用现有读写与 Passkey 安全实现，保持旧创建默认；无数据迁移、无查看即 commit。

放行：旧库全部类型可看；同一个旧项目从各入口的身份一致；原数据库字节/内容版本/同步状态不因阅读变化；纯 Token、单笔记及设备绑定 Passkey 不退化。

## 阶段 2：存储原型与兼容准备

仅用虚构临时数据验证本地加密扩展 + Room 协调、KDBX 单 Entry 扩展、MDBX 原始 payload 保留、Bitwarden 单 Cipher 扩展和权限/容量。选定经过测试的最低兼容版本，先发布保留未知内容的 reader/writer。

放行：写入与恢复过程中杀进程不会导致混合项目被当作保存成功但缺内容；旧版普通编辑不会覆写其他组件。验证失败的后端保持混合写入关闭。必要时明确选择统一存储迁移，不隐瞒额外文件的格式变化。

## 阶段 3：可选新建与完整联动

接入 EditorHost、类型编辑模块、统一 DraftStore、组件补丁、批量计划与结果回执。新建试用默认关闭，已有混合项目始终可读。

逐项迁移自动填充/无障碍/键盘、Credential Manager、导入导出、回收站、移动与去重的写入路径。未经统一仓库处理的整行回写入口未清理完，不能向真实库开放混合项目创建。

## 阶段 4：测量后使用 Rust

复用 Android 的 rust-core / rust-jni 边界，不先另造一个新的运行时。

Rust 适合承担：

- 按版本解析保留未知结构的扩展、校验组件 ID/关系/大小、生成不含秘密的投影摘要。
- 增量更新项目→组件索引、过滤/排序、组件补丁与三方差异规划。
- 跨库转换和导入时的分批校验；加解密继续既有审核路径，不因 UI 重构重写签名算法。

Compose/Kotlin 保留：局部可观察草稿、焦点与导航、组件布局和展开动效、Android 安全存储与系统凭据回调、生命周期取消。不能把每次输入和每个 OTP tick 都转成全库 JNI 请求。

建议原型 FFI：`projectSummaries(cursor, byteBudget)`、`loadComponent(itemId, componentId)`、`planPatch(baseRevision, patch)`、`applyProjectionDelta(changedIds)`。这只是职责说明，不是已实现 API。

默认预算从保守值开始实测：每批最多 128 个项目摘要，同时不超过 1 MiB 输入；输出同样有字节上限。正文/附件走按需块读取，单个大项目不套用摘要条数绕过字节限制。超过预算返回续读游标或明确错误，不截断后显示成功。这些是原型目标，不能覆盖 provider 更小的限制，例如原生 Token 的 16 KiB。

项目组成的一个原子写入组不能拆开后分别宣布成功；可以先暂存大内容块，再原子发布目录。限制递归深度、组件数、UTF-8 字节、解压后字节和输出膨胀；使用 checked 长度计算、超时/取消和背压。不能把整个加密库解密成一个 String 再同时复制到 Kotlin 和 Rust。

秘密不进索引/日志/崩溃 toString；明文缓冲及时释放，可控缓冲归零，但不宣称 JVM String 能可靠擦除。锁库使缓存和共享进程句柄失效，Rust panic/解析失败转成有类型错误。

## 有针对性的功能矩阵

| 场景 | 本地 | KDBX | MDBX/MDBX2 | Bitwarden |
|---|---|---|---|---|
| 旧单组件只读/编辑 | 主记录不丢字段 | UUID/保护/历史保持 | 类型/逻辑 ID 保持 | 原生 Cipher/密钥保持 |
| 登录 + 两篇笔记 + OTP | 1 原项目、4 入口 | 1 Entry、4 入口 | 1 逻辑对象、4 入口 | 1 Cipher；扩展能力通过才开启 |
| 单改第二篇笔记 | 第一篇和密码字节语义不变 | 同左，保留未知字段 | 同左，无无效 commit | 同左，不覆盖同 Cipher Passkey |
| 归属与移动 | 全组件同权限 | 解锁/失效 URI/外部修改 | 锁库/远端并发 | 组织权限/离线/服务端冲突 |
| 中断、重试 | 扩展与 Room 崩溃恢复 | 文件安全替换与回执 | 原子组/分批恢复 | 不重复 Cipher/附件 |
| 降级往返 | ID 复用/旧备份/删除 | 外部编辑/模板/历史 | 旧 payload writer | 官方客户端/自托管差异 |
| 导出与导入 | 带扩展映射、只选目标库 | 加密与附件 | 流式进度/大小限制 | CXF 子集与 Passkey 迁移限制 |

重点用例：

1. 同名但不同 ID 的两篇笔记，编辑/排序/移除不串项；独立笔记编辑仍是原流程。
2. 旧 boundNoteId 被多个密码引用、跨库绑定、同名不同库、重复 provider credential ID，不自动合并。
3. 密码列表点进项目→笔记→原项目→返回，位置和草稿保持；从笔记列表进入时返回原列表。
4. 单独验证码项目不出现空登录字段；TOTP 展开不生成内容变更；HOTP 预览不自增。
5. 项目级删除时选中两篇笔记只处理根一次；组件级移除不会删整项目。移动失败保留来源。
6. 批量 5 项、公共设置、逐项覆盖、两个目标，数量准确；部分成功重试只补缺项，取消不误报完成。
7. 不可导出设备私钥、导入非零计数规范限制、远端 Passkey 归属/计数原样；真实 Credential Manager 验收独立于合成验签。
8. 新→兼容旧→新：编辑主密码、删除主记录、恢复旧备份、外部字段编辑和附件删除逐个比较；不把「开库成功」当作降级完整通过。
9. 10,000 个普通项目、单项目 1,000 组件、长笔记/大附件组合；超过能力返回原因、不 OOM、不静默少导入。
10. 所有导入先选目标、解锁/ZIP 解密顺序正常；完整备份只导出选定库，扩展索引不重复生成副本。CSV/CXF 无法表达完整项目关系时明确结果，不能宣称无损。

## 性能与 UI 验收边界

采集同设备同样本前后首屏可交互延迟、详情内容就绪延迟、P95/P99 帧耗时、主线程阻塞、峰值内存与取消后资源回收。首次索引和增量读写分开记录，不以空库截图或桌面 Rust 微基准代替 Android 结果。

复用公共 AVD `Monica_Issue136_API_32`，先检查是否已启动；只在确实需要其他 API/ABI 时补覆盖。真机 Credential Manager/其他密码管理器往返仍需实际设备。

UI 至少覆盖：320/360/412dp、长译文、1.3/2.0 字体、TalkBack、软键盘、RTL、明暗色、减少动画、长秘密显隐与单手保存。Canvas 只验证设计可读性；不会由截图证明拖拽/焦点/原生布局已通过。

通过相应阶段才继续，不在纯设计阶段构建 APK、启动 AVD 或无目的跑全套测试。
