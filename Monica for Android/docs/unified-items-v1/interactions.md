# 页面与操作契约

所有画面都是设计稿。坐标/固定高度用于展示状态，原生实现应随文字、字体与窗口重新测量，不能照抄为固定表单高度。

## 新建入口与模板

从密码列表点新建，直接进入账号模板；从笔记、验证器、卡包进入时采用对应模板，承接当前数据库和文件夹，不增加必经向导。只有从全局新建或手动点「模板」时才选择模板。空白项目也必须添加至少一份可保存内容。

模板：账号、笔记、验证码、开发凭据、银行卡/证件/地址、二维码、Wi-Fi、空白。开发模板提供账号、SSH/API 等起点，但不自动生成密钥或塞满所有区块。

有内容时更换模板只能明确追加所需组件，不能清空旧内容，也不能悄悄在另一个草稿保存。密码模板仍可使用熟悉的「新建密码」标题；这是创建入口的名称，不成为限制用户继续添加内容的类型锁，增加笔记时也不突然跳换标题。

页面顺序：顶栏 → 大标题 → 模板选择 → 存储位置 → 项目名称 → 当前内容 → 添加内容 → 保存。采用同一个滚动表单，右下保存 FAB 始终可达。

按最新反馈，顶栏只放返回、收藏、更多。大标题下方是紧凑、居左的模板按钮组：左段显示图标与当前模板名（如「密码」），右段为展开箭头；不再显示占满行宽的「模板 · 密码」。点击名称或箭头均打开模板选择，不重置或重新生成当前草稿；读屏作为一个选择控件朗读「模板：密码」。按钮组随内容滚出。下滑时，大标题「新建密码」连续收起并移动到顶栏，只有标题固定，模板控件不粘顶。回到顶部时反向展开；不同时出现大小两份标题，不因达到阈值突然把整页顶动。旧类型独立草稿方案也采用相同的标题/类型位置，但不与本方案的模板语义混淆。

## 添加内容与局部追加

两种动作分工明确：

- 区域内「添加更多」继续增加同类项，例如账号、笔记、自定义字段、附件。已有项每个都有固定可点的三点菜单。
- 页尾「添加内容」在表单内展开类型选择区，用于首次加入 SSH、API Token、卡片等其他组件。选择后收起选择区，新组件在当前位置展开；不每次都弹巨大底部面板。

URL 区保留并排「添加 URL / 绑定应用」按钮，按文案宽度组成紧凑组并靠左，外侧大圆角、内侧小圆角；表单与数据卡片仍使用原宽度。账号凭据默认完整显示，其他资料按需加。新方案不新增第三方登录，但旧 SSO 信息可见且原样保留。

### 紧凑按钮规格

- 模板组视觉高度 40dp，名称段按内容宽度，箭头段约 44dp，中缝 2dp；外角 20dp、内角 6dp。名称段仅呈现当前模板，完整语义由读屏标签补足。
- 「添加 URL / 绑定应用」视觉高度 40dp，宽度随文案，中缝 4dp、外角 20dp、内角 6dp；保留两个独立动作。普通「添加内容 / 添加更多 / 添加附件」为同高度的短胶囊，全部居左。添加验证码保持轻量文字动作。
- 按钮文字默认 14sp，视觉紧凑但每个触控区域至少 48dp，彼此不重叠。按压背景裁剪到本段圆角，不出现矩形白边。
- 长译文先增加内容宽度；空间不足时换行并保持居左，跨行的按钮各自恢复完整圆角。字体放大时按钮与触控区域一起增高，不缩小文字或截断动作名。
- 保存 FAB、表单宽度、区块归属与标题滚动保持原设计。按钮变小不把整页压成密集表格。

同类内容多份时，以名称、局部摘要区分；编辑一份不会折叠或重建另一份正在输入的内容。重复项的三点菜单：重命名、上移、下移、移出为独立项目、移除。整理模式才显示拖动柄，保留菜单和无障碍操作。

## 内容编辑与详情分工

| 内容 | 新建/编辑 | 从对应列表打开 |
|---|---|---|
| 登录账号 | 用户名、密码、网站及关联验证码，组尾继续添加账号 | 共用项目详情，定位该账号；可继续看同项目其他内容 |
| OTP | 密钥、扫描、算法/周期按需；HOTP 预览不消费计数 | 共用详情中的验证码区；单独 OTP 项目只呈现该内容 |
| Passkey | 系统注册/规范导入后选择归属；已有合法凭据可移入 | 共用详情的通行密钥区，原身份/计数/归属保持 |
| 笔记 | 全屏正文/Markdown 编辑，完成后回到所属项目草稿 | 保留笔记阅读页，顶部轻量「来自 工作账号 →」跳回原项目 |
| SSH / GPG | 导入或生成后显示指纹、算法、材料摘要；私钥按需展开 | 共用详情中的密钥模块；公私钥材料页带原项目入口 |
| API Token | 提供商、令牌、端点；更多参数按 schema | 共用详情中的令牌模块；复制令牌不等待同步 |
| 二维码/条码 | 内容、码制、扫描/图片；有效后预览 | 保留适合出示的全屏码页，附原项目入口 |
| Wi-Fi | SSID、安全类型、密码；更多参数按需 | 共用详情中的网络模块，可打开二维码出示页 |
| 卡片/证件/地址/支付信息 | 复用现有专用字段与校验；照片、额外资料按需 | 共用详情中的对应内容，卡面/图片可全屏 |
| Steam | 继续现有专用编辑、令牌与交易流程 | 继续现有 Steam 详情，不嵌入统一项目的可写聚合 |
| Send | 是独立分享对象 | 继续现有分享流程，不把临时链接当原项目组件 |

这轮没有补造当前尚未实现的支付账户编辑功能；表格是最终能力规划。每种组件须通过目标能力与读写验收后才开放。

## 共用详情

标题、数据库、收藏、编辑与更多采用相同骨架。多个组件用轻量「内容 · 7」入口跳到相应区段，不把所有类型挤成一排胶囊。

从某个组件入口进入，先定位该内容；其他内容按实际顺序继续显示。单组件项目不出现空的账号/笔记/密钥区。笔记详情从原项目返回列表时保留原滚动位置；从笔记跳原项目再返回，应回到原笔记，而非密码首页。

详情中的「笔记 · 2」展开当前项目的两篇笔记，点击即可读正文，不绕到全局笔记列表。「添加内容」先进入当前项目的编辑草稿，不在阅读状态直接修改已保存的数据。

密码隐藏时保持简洁固定掩码；显示长密码时卡片高度平滑变化。私钥、Markdown、二维码预览懒加载。展开只动画当前区块与后续位置，不整页 Crossfade，不每秒让 OTP 带动整页重组。

## 两篇笔记的完整路径

    密码项目「工作账号」
      ├─ login-a
      ├─ note-a「部署说明」
      └─ note-b「恢复步骤」

笔记列表出现两行，副标题同为「工作账号 · 工作库」。点「恢复步骤」进入 note-b 的阅读页，编辑只产生 note-b 的补丁。保存后更新原项目 revision，并通知项目详情及两个列表入口；未编辑的 note-a 保持不变。

新建项目尚未保存时，笔记编辑页的「完成」只写入同一个内存草稿，不提前落一条独立笔记。正式项目中的笔记编辑则通过项目仓库保存，显示对应结果。两种状态按钮与退出提示一致，不用「完成」制造已经持久保存的错觉。

## 批量新建

「添加账号」与「批量新建」不混用：

| 模式 | 保存结果 | 适合情况 |
|---|---|---|
| 一个项目，多份内容 | 1 个项目，多个账号/笔记等组件 | 同一服务的账号、部署密钥和说明一起管理 |
| 批量新建 | N 个独立项目 | 学校/工厂等同时建立多组独立账号 |

批量入口放在模板选择和新建更多菜单，不占普通首屏。流程为：公共设置 → 项目清单 → 当前项目的覆盖内容 → 保存预览。

公共设置只提供数据库、文件夹、网站、初始内容模板等默认值。用户名/密码不能无提示共用；密码生成默认逐项独立。选择公用密码必须主动操作并能从预览看到。HOTP、Passkey、设备绑定密钥不能作为公共内容自动克隆给所有项目。

底部编辑栏只显示当前范围：「公共设置」或「项目 2 / 5 · 工厂账号」，并有返回清单入口。不会同时显示一条选中公共设置的长栏和另一个独立凭据全名。覆盖值可选择恢复公共默认值。

保存预览明确显示：5 个独立项目，目标工作库；若另存一个副本，显示 5 × 2 个目标结果。公共字段在创建时展开为快照，之后修改一个项目不修改其他项目。

保存中有进度及可查看的项目结果。按 operationId 和项目/目标身份续传，只重试失败项；不能因一个远端失败把已成功上传的项目再创建一遍。主记录、内容块、附件阶段分别记录，不能把「已排队」说成「服务器已完成」。

## 归属、移动、删除与回收

数据库选择使用现有统一选择器，单一主位置清楚可见；高级「另存副本」保留多目标能力。组件继承整个项目的权限和归属，移动组件必须显式「移出为独立项目」。

- 文件夹移动：移动原项目一次，所有列表入口一起变化。
- 跨库移动整个项目：预检查全部组件、私钥可移植性、附件权限和容量，完成目标写入/回读验证后再处理来源。未支持的一部分不能静默遗留在旧库却标成功。
- 组件菜单「移除这篇笔记」只移除当前 note；「删除整个项目」在项目更多菜单，确认列出受影响内容数量。
- 移除账号时，关联 OTP/Passkey 必须显式选择保留为未关联内容、重新关联或一同移除；默认保留，不能悄悄销毁密钥。
- 移除主组件时先确定下一个可用主组件及后端映射；最后一份内容被移除时明确转为删除项目，不能写入无法被旧版理解的空壳。
- 回收站以原项目为单位，展示内容计数，数据库筛选跟随原位置。恢复整个项目保持组件 ID 和附件关系。
- 组件删除在草稿保存前可撤销；保存后依已实现的项目历史/后端历史恢复，不假定任何库都有单组件回收站。
- 批量选择到同项目多个入口时，项目级移动/删除按 itemId 去重；组件级移除按 componentId 分别计数。确认文字明确对象，不能显示「删 2 项」实际删掉整个项目。

## 冲突与外部编辑

不同组件并发修改，在完整基准可用时三方合并。例如本机改 note-a、远端改 login-a，应保留两者。同一字段的修改与删除冲突进入选择页，分别展示当前组件的双方版本与来源，秘密默认隐藏。

重排与内容修改分别合并；删除组件使用明确 tombstone，不能把缺失字段一概解释成删除。没有共同基准时保留双方并提示选择，不盲目按 updatedAt 覆盖。合并后提交仍需后端的版本前置条件，不能把本地合并成功当远端提交成功。

## 试用与旧方案

设置「新建与编辑」提供经典（默认）和统一项目（试用）。试用开关只选择新建/编辑入口，不改变签名行为或后台同步来源。

关闭后，旧普通项目仍走经典界面；已经保存的混合项目必须继续能完整读取，编辑时使用能保留所有内容的编辑器。若需实际回退 APK，另用兼容导出流程，不能把关闭开关冒充降级转换。

## M3E 与可访问性

左右 12dp；字段卡片组外侧 24–28dp 圆角，内侧 8dp、4dp 间隔。紧凑按钮另按上方 40dp 高度、20dp/6dp 圆角规格。按压反馈裁剪在圆角内，避免白边。尽量复用已有字段、数据库磁贴、设置选项和 Monica 展开动效。

48dp 最小触控区，图标有对象明确的语义。长语言允许换行和自然增高；不是所有卡片强制同高。窄屏将并排动作改为共享行高或纵排，保存 FAB 不遮挡末项/键盘。RTL、字体放大、键盘和读屏须在原生阶段验证。

动画初始建议 180–240ms，低幅度弹性；新增行、长文本显隐与局部折叠使用稳定 key 保持光标和滚动锚点。遵循系统关闭动画。图上的「9:41」、示例用户名和验证码均为演示数据。
