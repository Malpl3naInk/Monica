# V2 放行标准：数据正确，再谈默认替换

以下是**将来实施的验收计划**，不是已完成的测试报告。本轮没有构建 APK、写应用功能或执行数据库保存测试。

## 数据库能力矩阵

“沿用”表示当前源码已有相应入口/适配方向，仍需按新旧往返实测；不表示此设计阶段已确认所有字段可用。每一项还要细分账号权限、附件许可、锁定状态与数据库格式版本。

| 类型 | Monica 本地 | KeePass | MDBX（旧格式 / MDBX2） | Bitwarden |
|---|---|---|---|---|
| 密码 / 多凭据 / 网站 / OTP / 应用 | 沿用 PasswordEntry 与关联模型 | 标准字段 + 既有扩展，逐字段核对 | 双格式都测，身份与文件夹不变 | Login、URI、TOTP + 扩展；多凭据不能假定原生一条能容纳 |
| SSH / GPG / Wi-Fi / 条码 | 沿用各自现有模型 | 原格式与保护属性往返 | SSH/GPG 依现有跨客户端契约 | 逐类型验证现有转换器和服务器能力，不假定 GPG/SSH 都有原生类型 |
| 验证码独立条目 | SecureItem 与密码绑定均测 | OTP 标准/扩展往返 | 计数器、周期、算法保留 | 核对独立条目表示与 Login TOTP 关联，避免双份 |
| 银行卡 / 证件 / 地址 / 笔记 | SecureItem / 既有笔记模型 | 标准/扩展与附件 | 对应 payload、collection、扩展 | Card / Identity / SecureNote 等既有映射；字段能力单独验 |
| API Token | 不新增通用本地类型 | 不扩大范围 | 保持现有原生支持边界 | 不扩大范围 |
| Send | 不冒充本地条目 | 不适用 | 不适用 | 仅现有 Send，文本/文件权限分别验 |
| KeePass 原生字段/模板 | 不转成 Room 密码 | 原生 UUID、分组、历史/版本、保护字段 | 不适用 | 不适用 |

允许使用经典页回退覆盖尚未放行的组合；不可伪造可保存的目标。服务器或数据库不支持某字段时，只能明确阻止/请求用户选择，不悄悄丢字段，也不因一个目标不支持就从所有目标中删除该字段。

## 必须锁定的存储契约

1. **未改字段不变**：使用原对象 + 变更集；未加载/读取失败/未知字段不是空字符串。保留 SSO、passkey、SSH、GPG、自定义字段及副本元数据。
2. **明确删除**：折叠与重排不产生删除；删除组件才标记相关字段 tombstone/显式清空。移除未提交附件不删除数据库原附件。
3. **原生身份不变**：Room ID、KeePass UUID、Bitwarden cipher ID、MDBX 物理/逻辑 ID 各走原通道。新 UI 不自行生成另一套身份。
4. **加密边界不变**：本机密文不写入共享 payload；私钥、公钥、指纹与保护位保留；格式不靠 trim 或 UI 格式化“修正”。
5. **多目标结果完整**：每个目标 × 每个凭据都有身份、状态与错误；部分失败保留编辑态。新增重试不能复制已成功目标，更新重试遵守最新版本冲突。
6. **本地持久化与同步区分**：Bitwarden 队列落盘才能显示“已保存，待同步”；服务器确认后才“已同步”。认证失败、组织只读、网络中断都不能被当作成功。
7. **外部文件真实写入**：KeePass/MDBX 保存返回后关闭重开验证，不以 Room 镜像存在代表原文件成功。权限撤销、文件替换、版本冲突有明确失败结果。
8. **附件分阶段**：主记录已保存而附件失败，提示“条目已保存，附件未完成”；继续同一条目重试附件，不能删除主记录或重复创建。
9. **会话及并发**：保存中锁定、退后台、重复点保存、类型切换、网络重试和进程重启后无重复记录。不得用全局忙状态阻塞其他条目的编辑。
10. **跨客户端验证**：SSH/GPG 至少以现有规范测试 Android → CLI 格式往返，真实 CLI 互通由另一会话协作，不改 CLI；模拟格式通过不可写成真实 CLI 已通过。KeePass 与 Bitwarden 需独立客户端重开核对。

## 测试数据与关键用例

每个已支持的“类型 × 库”至少走：经典新建 → V2 打开只改名称 → 经典重开；V2 新建 → 经典改备注 → V2 重开；完整导出/导入后对比规范化结构。新建、编辑、复制、当前文件夹快捷新建、扫描/生成器返回均覆盖。

| 场景 | 要核对的结果 |
|---|---|
| 最小密码 / 只有用户名 / 空密码 | 沿用现有合法性约定，不为了简洁 UI 新增错误必填 |
| 联系/地址/支付原本非空但未操作 | 自动显示，改名称后完整保留；可选移除才清空 |
| SSO 旧条目、失效引用、未知提供商 | 只读摘要不崩溃；一般字段编辑原样保留；不允许手动创建/复制成新 SSO；导入同步不受阻 |
| 1 / 2 / 多组凭据 | 各自用户名/密码/OTP/附件正确，公共字段与顺序不串组 |
| TOTP/HOTP、自定义周期/位数/算法、非法密钥 | 参数不被默认值覆盖；HOTP 预览不消费计数器；错误不泄露密钥 |
| SSH Ed25519 / RSA，私钥末尾换行与未知内层属性 | 指纹、公钥、私钥逐字节或规范契约一致 |
| GPG 公钥-only、私钥有/无口令、多公钥块、导入已有材料 | 不把公钥-only 判成无效；不把私钥写进公钥字段；缩短材料清理旧分块 |
| 附件空/多/大文件、照片正反面、取消文件选择 | 正确关联当前草稿/凭据，取消不建条目；摘要先显示，后台流式处理 |
| Unicode、emoji、超长名称/URL/备注、意大利语/中文/德文 | 不截掉数据；布局可换行，校验与编码一致 |
| 未知扩展、未知 schema、不可解密字段 | 原样保留；无法无损更新就阻止，不保存一个“干净但丢数据”的对象 |
| 两目标成功 + 一目标失败/未执行 | 精确列状态，重试失败目标后身份与数量正确；不显示笼统“保存成功” |
| 创建后端失败、附件失败、断网、只读库、权限撤销、磁盘满 | 不假成功，草稿可继续；已写入与未写入状态明确 |
| 同条目外部改动、保存前移动文件夹 | 冲突提示与刷新/重选流程，不覆盖新版本或回落错误目标 |
| 自动锁定、旋转、返回、重复点击、进程被杀 | 旋转不丢当前内存草稿；锁定/进程退出遵循敏感草稿策略；不存明文到恢复状态 |

未知外层 MDBX payload 保留是已有实现的已知缺口。V2 试验开关覆盖到这类条目前，必须补齐 adapter 或限制为不会覆盖其 payload 的操作；“退回经典页”不是无损的证明。

## 性能测试设计

不把少量字段的速度提升预先归功于 Rust。分别测导航/组合、候选载入、解析/JNI、加密写入、网络同步。以下阈值是**初始工程目标**，实现前确定固定中端参考真机；公共模拟器作相对回归，不能替代真机绝对指标。

| 指标 | 初始目标与测量方式 |
|---|---|
| 点击新建 → 首个有意义可见帧 | 解锁且进程暖态 P95 ≤ 150ms；用输入事件及首帧 trace 标记，不用点击回调开始时间替代 |
| 点击新建 → 核心字段可输入 | 暖态 P95 ≤ 250ms；进程冷启动另记（解锁/读库/密钥加载单列），不得混入暖态平均值 |
| 字段增删、滚动、键盘、整理重排 | 60Hz 参考机 P95 帧时长 ≤ 16.7ms、P99 ≤ 33.3ms，重复出现 >50ms 主线程长帧必须分析；动画时长不等于输入阻塞时长 |
| 首次与连续进入 | 每类 5 次预热 + 30 次记录；另测首次解锁后的第一开，报告 P50/P95/极值和超时率 |
| 大库压力 | 100 / 1,000 / 10,000 条记录，核心字段可输入不应依赖全库候选加载；多附件和长 GPG 材料单独测试 |
| Rust 候选 | Kotlin 与 Rust 在相同输入和结果契约下测，包含 JNI、分配、编码、首次加载、取消；小输入保留轻量路径，不能只报告 Rust 内部耗时 |
| 内存 | 连续打开/退出 30 次，核查草稿/位图/密钥任务是否释放；记录 Java/native heap 与 PSS 曲线，不能靠全量预加载换首屏指标 |

构建与性能测量分开，主机空闲、同版本系统、同显示设置、同数据集、相同调试/发布模式，新旧 APK 交替测。优先 profileable/release，debug 只作诊断。沿用公共 `Monica_Issue136_API_32`；先检查是否已运行，本任务启动的才在结束后停止。保留旧优化 trace 作定位参考，不将旧的帧时长统计冒充点击到可交互时长。

Keyguard 可使用允许免费测试的构建对比；若只有源码，报告源码差异并明确无运行时对比。禁止为了做基准跳过许可确认。

## 原生 UI 验收

- 320/360/412dp、横屏/窗口缩放、1.0/1.3/1.5/2.0 字体、明暗/动态色、长译文、RTL、TalkBack、硬件键盘。
- 名称/密码输入、生成返回指定字段、添加/删除/撤销、重排、切换多凭据、切类型再切回、键盘避让、最后一项可滚到、保存失败定位。
- 生成器/扫描返回不能重置归属和收藏；GPG/SSH 重计算迟到不能覆盖新草稿；非密码类型收藏与保存具有真实数据效果。
- 组件读取顺序、48dp 点击区域、焦点稳定、关闭动画后仍可用；私钥/密码默认隐藏，截图保护保持用户设置。
- UI 录屏需使用合成条目，记录截图来自 Canvas 还是 Android。M3E Web 组件的视觉核查不计入原生 Compose 通过项。

## 开关放行门槛

按类型和目标维护能力登记表，要求：读写往返测试通过、失败与幂等测试通过、旧 UI 可打开新数据、没有数据格式迁移、可回退、原生布局检查通过、性能不退化。未达到就留经典页。

默认替换必须另行评审：全部公开组合通过，至少两个测试版反馈周期无未解决数据丢失/重复/错误归属；不能仅凭页面好看或几次成功保存就删除旧方案。

## v2 新增验收：重复追加是主路径

- URL、自定义字段、附件分别添加 0 → 1 → 2 → 多项；每次新增后本区追加按钮仍存在（URL 区保留“添加 URL / 绑定应用”按钮组），不进入全局 bottom sheet。
- 修改/排序/移除第二项，其他项目的内容、保护属性、身份及附件引用不变；保存并重开核对每一项和顺序，不只验第一项。
- 自定义字段同名、长值、混合保护类型；多附件同名与某个失败；网站不同匹配规则，分别验证。
- 已达后端数量上限时明确提示；后端不支持的重复区不显示虚假的新增入口，切换目标不静默截断。
- 其他资料默认仅占页尾一行，展开/折叠不干扰常用重复区；已有资料仍保留。

## v3 新增验收：按钮组与逐项三点

- 空/单项/多项 URL 状态都出现紧凑居左的“添加 URL / 绑定应用”，检查 40dp 视觉高度、外侧 20dp、内侧 6dp、中缝 4dp，触控区域至少 48dp；两按钮独立焦点、按压反馈和点击区域。
- 所有重复卡片右侧都有竖向三点；点击第二项后菜单只修改或删除第二项，不串项；移除前后稳定 ID 保持。
- URL、自定义字段、附件以及应用绑定分别检查菜单动作；未保存附件的删除不删原库附件，解除绑定不删 URL。
- 大字体/长译文下按钮组可读且可点，三点与密码显示开关不重叠；TalkBack 能识别菜单所属项目。

## v6 验收：紧凑正文类型选择与标题收起

- 展开时大标题下方有紧凑居左的类型名＋箭头按钮组；两段均打开选择，不重置当前草稿。下滑后按钮组随正文滚出，大标题连续收进顶栏。不会出现两份标题、固定类型控件或阈值处页面抽动。
- 六种密码子类型分别进入，当前项有选中标记；切回恢复各自输入与滚动位置，生成器迟到结果不覆盖其他类型。
- API Token 目标不兼容时显式选择 MDBX，取消后原类型、归属与草稿不变；只保存当前类型。
- 320dp、1.5/2.0 字体和长译文下，正文类型组与追加按钮自然扩宽/增高，放不下时换行居左；触控区至少 48dp、互不重叠。顶栏不增加固定的第二排选择控件，读屏能读出完整类型和标题。
- 已有条目编辑不暴露无效类型转换；卡包仅显示其适用类型，专用页面不出现无效切换入口。
