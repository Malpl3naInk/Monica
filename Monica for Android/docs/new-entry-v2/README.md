# 新建页 V2：按需组装的条目编辑器

2026-09-20 · 设计提案 v6 · **尚未实现，不改变当前 Android 行为**。

最新修订：类型选择在大标题下采用紧凑居左的名称＋箭头按钮组；添加 URL／绑定应用、添加更多等也缩至内容宽度并靠左。下滑后「新建密码」标题收进顶栏。后续数据模型升级另见 [统一项目方案](../unified-items-v1/README.md)。

本轮仅产出设计、可编辑 M3E Canvas 和后续验收方案。原页面继续作为默认方案。设计参考用户的 Keyguard 截图与已核对上游主分支的源码，不以截图或源码分析代替运行性能测试。

核心体验：进入即能填写名称、用户名和密码；网站、验证码有直接入口；URL 区使用“添加 URL / 绑定应用”按钮组，自定义字段、附件等在各自区域底部“添加更多”，都可重复操作。低频的个人、地址、支付资料仅收在整页末尾“其他资料”中。收藏、类型选择、存储位置、保存的操作位置在所有适用类型中一致。

### 01 / 新建密码

从上到下：

1. 顶部仅返回、收藏、更多；大标题“新建密码”，滚动后连续收进顶栏。类型选择是大标题下面靠左的小按钮组，左段为图标＋类型名，右段为箭头，随表单滚出；点击名称或箭头均打开选择。收藏仍写 Monica 现有收藏字段。
2. 一个紧凑的存储位置磁贴：“个人密码库 / 常用”，能直接点开选择；多选时显示“个人密码库 + 1”，详情列出全部目标。数据归属始终可见，不藏在“添加更多”中。
3. 名称（独立字段）；用户名 / 密码（相连字段组）；网站（第一条）。用户名与密码各自保留生成器/常用账号入口，密码保留显示开关。
4. “添加验证码”轻量动作，只在需要时展开密钥、扫描/关联已有验证码；不为未添加的 TOTP 建立计时和解析任务。
5. 继续向下是网站、自定义字段、附件等各自的追加区。每区有小标题、已有项目列表和组尾追加操作（URL 区为“添加 URL / 绑定应用”按钮组）；空区也保留标题与按钮，明确可新增。个人、地址、支付信息不占这些主要区域，只在页尾“其他资料”中按需展开。
6. 右下角“保存”扩展 FAB。下滚时收成图标、上滚或输入报错时展开。键盘出现后停在键盘上方，列表底部留足空间，不压住最后一项或错误信息。

第一版不自动展开键盘，进入后可立即点击输入；保留现有自动聚焦偏好（如有），且只请求一次焦点。扫描/自动填充带入的数据直接出现在相应字段，不先展示空表单再覆盖。

### 02 / 分区的“添加更多”：这是主操作

参考 Keyguard 截图的组织方式：**小标题 → 已有项目 0…N → 本区追加操作**。它们是同一页面可滚动的多个区，不是一个全局字段商店，也不要求先打开 bottom sheet 再决定加什么。

| 区域 | 追加操作 | 多项与操作 |
|---|---|---|
| URL / 应用 | “添加 URL”直接插入网址行；“绑定应用”打开现有应用选择流程 | 0…N 个，各自保留 URL 与匹配规则；逐项编辑、上移/下移、移除 |
| 自定义字段 | 按钮附近小菜单选文本、隐藏值等已支持类型，再插入本区 | 0…N 个，每项独立名称、值、类型、保护状态与稳定 ID |
| 附件 | 打开系统文件选择器，支持多选；再次点击继续添加 | 多文件逐项显示名称、大小、进度和错误；逐项重命名/移除；不重建其他附件 |
| 多组账号 | 在账号区追加一组，再切到新账号 | 每组用户名、密码和验证码独立；不能把一组账户的两个密码误作两个自定义字段 |
| 标签 / 关联条目等 | 仅在该类型和后端已有能力时显示本区入口 | 允许现有模型支持的多个项目；不为复制截图新增尚无存储契约的功能 |

添加一项后，追加按钮（URL 区为双按钮组，其他重复区为“添加更多”）仍留在**该区列表末尾**，不是变成“已添加”或消失。新增行在按钮之前展开，焦点移动到该行；旧行内容、光标和滚动锚点保持。自定义字段选类型可用局部弹出菜单，附件可用系统选择器；这些是完成具体动作所需的选择，不是全局 bottom sheet。

默认至少展示网站、自定义字段、附件这些常用重复区（以当前类型能力为准）。空区只有小标题和轻量追加操作，不塞解释卡片；区间约 24–32dp，保持 Keyguard 的清楚分区，同时不照搬大字体截图里的巨大空白。第一屏与下面各区是同一个连续表单，图中的 A1/A2/A3/A4 表示不同滚动位置与数据状态。

备注为单一正文，显示“添加备注”而非暗示可以无限追加。普通密码的主用户名/密码、单账号绑定验证码也不为追求形式统一伪造多项；多账号通过独立凭据模型处理。所有后端数量限制要明确说明，不静默截断列表。

**“其他资料”是页尾一行文字入口**，放在常用重复区与备注之后；默认不显示“附加资料”标题、大卡片或资料总览。点击可展开紧凑选项：联系方式、地址、支付信息。只展开选中的组，不弹出大面积资料 bottom sheet；已存在非空旧资料仍自动呈现，避免隐藏用户已有内容。

卡包仍独立管理。地址/支付组里可以“从卡包填入”，复制资料快照且不建立绑定；不把这个低频入口提升到常用字段之前。地址/支付组保持现有单例存储契约，不能画出多个地址却在保存时只留下最后一个。邮箱/电话等已有列表能力则允许逐项追加。

### 当前画布阅读方式

- A1：密码核心区及网站第一项，网站下仍有“添加 URL / 绑定应用”按钮组。
- A2：下滑后的空重复区；网站、自定义字段、附件各有独立追加按钮，其他资料仅在页尾。
- A3：两个网站、两个自定义字段同时显示，证明可以反复添加。
- A4：两个附件及其中一项的操作菜单，组尾仍可继续添加。
- 其余类型画面只展示首段核心字段；图上的“向下继续”是草图注释，不是拟上线的 UI 文案。接续区统一使用上述分区追加规则，但按各类型/目标实际能力显示。

### URL 双按钮组与每项三点菜单（v6 尺寸修订）

- URL 区文案固定为 **添加 URL**、**绑定应用**。按内容宽度并排成组、整组居左，两个动作独立；40dp 视觉高度、外侧 20dp 大圆角、内侧 6dp 小圆角、中间 4dp 留缝，共用 tonal 背景色。各区“添加更多”也使用同高度的短胶囊并居左。
- 添加 URL 继续在本区追加空行；绑定应用继续现有应用选择流程。绑定后的应用显示在本区并有右侧三点，提供“更换应用 / 解除绑定”。解除绑定不卸载应用，也不删除 URL。绑定数量遵守现有模型，不能画多应用列表却只保存一个包名。
- 触控区至少 48dp，按压背景遵循本段圆角。长译文先增加宽度，空间不足时换行居左，跨行按钮各自恢复完整圆角；大字体时同步增高，不缩字或截断动作名。不会退化为用“添加更多”模糊两个动作。
- **所有可重复添加卡片，右侧必须始终有可点的竖向三点按钮**：URL、自定义字段、附件、多凭据及适用的其他重复项。不是长按才出现，也不能用拖动柄替代；敏感值的显隐按钮放在三点左侧。
- 菜单锚定当前卡片的三点按钮。URL：匹配规则（沿用支持能力）、上移/下移、删除；自定义字段：重命名、上移/下移、删除；附件：重命名、上移/下移、删除，失败时可重试、上传时可取消。第一项没有有效上移、最后一项没有有效下移；未知后端能力不显示虚假操作。
- 删除只作用于当前项目，非空/已有数据确认后可在保存前撤销。附件删除标记进入本次草稿，未保存时不直接破坏原库文件；取消待上传文件不删除其他已保存附件。
- 菜单项名称保持明确，“删除”表示删除当前项，“解除绑定”表示取消应用关联。菜单标题只显示名称，不展示密码、恢复码或私钥。TalkBack 读出“URL 2 的更多操作”等具体对象。

[URL 按钮组与逐项菜单专用画布](canvas/06-url-actions.md) 展示绑定应用、URL 菜单、自定义字段菜单和附件菜单。

### 03 / 可动的组件

- 核心区（归属、名称、主凭据）位置固定；附加字段组支持折叠、展开、移除、调整顺序。网站、自定义字段和多凭据内部行也可调整顺序。
- 更多菜单中的“整理字段”进入显式整理状态，才显示拖动柄；长按拖动、边缘自动滚动。普通输入时不把整行设成拖动目标，避免妨碍选字与滚动。
- 每项都有“上移 / 下移 / 移除”菜单，TalkBack 和键盘可以完成同样操作。切换顺序依赖稳定字段 ID，不依赖数组索引，不丢输入光标和生成器返回目标。
- 折叠仅改变可见性。移除未保存的空组件立即完成；移除非空数据先说明将删除哪些内容，确认后提供撤销。保存前可恢复；保存后遵循现有历史能力，不假设任意数据库都有撤销历史。
- 核心字段不能通过整理操作删除。当前会话记住布局；自定义字段顺序沿用现有持久化语义。其他区块的显示顺序初版仅为本机界面偏好，不写进数据库自造同步字段。

### 04 / 所有条目的共同骨架

“必显”表示默认显示，不等于所有字段都必填。必填性、类型校验复用已有格式契约；不为界面整齐强迫用户填写不存在的信息。

| 类型 / 入口 | 默认显示 | 添加更多 / 二级操作 |
|---|---|---|
| 密码 | 名称、用户名、密码、首个网站；添加验证码 | 多账号、多网址、应用、备注、自定义字段、附件、联系/地址/支付资料 |
| 验证码 | 名称/服务、账号、密钥；扫描/粘贴；有效后预览 | 类型 TOTP/HOTP、算法、位数、周期或计数器；其他现有扩展。默认参数有摘要，非默认参数自动展开 |
| Wi-Fi | 名称、SSID、安全类型、密码（开放网络不必填） | 隐藏网络、备注、已有支持的扩展 |
| SSH | 名称、添加密钥区（生成 / 导入）；导入后公钥、指纹摘要 | 公私钥详情、注释、备注、自定义字段；生成参数在独立面板，不在首屏生成 |
| GPG | 名称、添加密钥区（生成 / 导入）；用户 ID、指纹、材料类型摘要 | 公钥/私钥操作、生成参数、备注、自定义字段；支持仅公钥；不预填巨型 armor 文本 |
| 银行卡 | 名称、卡号、持卡人、有效期 | 安全码、发卡行、卡面/照片、备注、自定义字段；受保护值默认遮蔽 |
| 证件 | 证件类型、名称、号码、姓名 | 签发/有效日期、签发机构、照片、国籍、扩展身份/地址、备注 |
| 地址 | 名称、收件人、国家/地区、街道、城市；地区/邮编按国家显示 | 联系方式、公司、楼层/门牌、备注；非中国地址不强制套中国必填规则 |
| 条码/二维码 | 名称、码制、内容；扫描/导入，有效后预览 | 备注及现有支持的扩展；不会把普通文本误判成通行密钥 |
| 笔记 | 名称、正文，正文优先获得空间 | 格式/Markdown、标签（仅此类型既有能力）、附件、自定义字段；输入时不每帧渲染 Markdown |
| API Token | 名称、提供商、Token、API 地址（按现有 schema） | 备注、自定义字段、导入 JSON；仍限定 MDBX 原生能力，不伪装成通用密码字段 |
| Send | Bitwarden 账号、名称、文本或文件、有效期摘要 | 密码保护、最大访问次数、隐藏邮箱/文本、备注等既有设置；主动作“创建链接”，没有虚构的收藏 |
| KeePass 原生新条目 / 模板 | 原生目标组、名称、原生字段列表 | 添加标准/自定义字段、保护属性、附件、模板标记；保持原生 UUID 与版本校验 |

卡包当前新建入口为银行卡、证件、地址。模型中有 PAYMENT_ACCOUNT 不代表有可用的新建页，方案不据此新增一套支付账户功能；未来接入也使用相同骨架。通行密钥仍由系统凭据创建流程产生，不能靠填写字符串手动“生成”。创建数据库/连接云服务属于数据库管理流程，继续沿用现有 MDBX 管理规范，不纳入本轮条目编辑器重构。

### 正文类型选择与滚动标题（v6）

[专用 M3E Canvas](canvas/07-type-switch.md)：类型放在标题下、打开选择、切到 SSH、标题收进顶栏四个状态。

- 顶栏顺序为返回 → 滚动收起后的标题 → 收藏 → 更多。展开时大标题下方是紧凑居左的类型按钮组，左段只显示图标＋类型名，右段为箭头；视觉高度 40dp、外角 20dp、内角 6dp、中缝 2dp。点击任一段打开类型选择，读屏作为一个选择控件，不增加重置草稿动作。
- 大标题是“新建密码 / 新建 SSH 密钥”等普通标题；下滑时连续收进顶栏，类型选择随正文滚出。顶部只保留一份当前标题，不用阈值跳变把表单顶动。返回顶部反向展开。
- 采用专用类型选择面板，单列“图标 + 完整名称 + 一行用途 + 当前勾选”。6 种类型不挤成横向小胶囊或一排难点的图标；密码、SSH 密钥、GPG 密钥、Wi-Fi、二维码/条码、API Token 均明确可辨。
- 面板仅负责条目类型，和页面内 URL/字段/附件的追加操作完全独立。当前项再点一次直接关闭，不清空草稿；切换新类型后关闭面板，先显示该类型可编辑核心区，密钥不自动生成。
- 有草稿的类型显示“有未保存内容”，不在面板泄露字段值。会话内各类型草稿独立；切回恢复字段、光标、滚动位置。首次切入新类型只复制允许继承的名称/归属/收藏，之后不覆盖该类型已有草稿。保存只提交当前类型。
- 后端不兼容的类型显示具体原因，例如 API Token 需要 MDBX。点选先给出显式更换目标选择；用户完成合法目标选择才切换，取消仍停留原类型和原目标，绝不静默换库或清空其他草稿。
- 320dp 或大字体时类型按钮组随正文自然扩宽/增高，触控区至少 48dp。顶栏不增加固定的第二排类型选择；收起标题采用标准可访问的单行标题布局，读屏提供完整名称。
- 类型切换用控件按压反馈、选中勾选和局部内容过渡；不要每切一次重建安全管理器或重复页面进入动画。完成切换后不抢焦点弹键盘；有输入需要才恢复聚焦。
- 编辑已有条目时不提供未经验证的任意类型转换，显示当前类型的只读标识；卡包的类型控件只列银行卡/证件/地址，不把其强塞进密码子类型列表。其他不可切换的专用页面不显示无效“切换”。

### 05 / 多凭据、类型切换、已有条目

另一组账号从账号区的“添加更多”加入。出现第二组后增加“账号 1 / 账号 2 / 管理”切换栏；默认只编辑当前组，名称/归属等公共字段仍独立。每组用户名、密码、OTP、附件及私有元数据绑定稳定 credential ID；切换不创建重复条目、不挪错附件。保存结果按“目标 × 凭据”核对数量与身份。

类型选择位于大标题下方并随正文滚动，收起时顶栏显示当前页面标题。会话中各类型分别持有草稿，切回来不丢内容；名称、归属、收藏可带入，类型专属字段不相互强转。只保存当前类型，退出时若有其他未保存草稿，明确提示一并舍弃。首版不提供已有条目的任意类型转换，继续沿用已验证的专用转换流程。此独立草稿语义属于本目录旧方案；后续统一项目以模板追加组件。

编辑旧条目时，**所有已存在的非空附加资料自动出现**，即使当前偏好没勾选该组件。解密/解析失败的字段标为“未能读取，保留原内容”，禁止用空值覆盖。未知扩展不能仅因为没有对应控件而丢弃。

第三方登录在新方案的类型列表与“添加更多”里彻底取消，也不能由复制/类型切换绕过新增限制。旧条目显示只读摘要“第三方登录 · 已有资料”，保留 loginType、ssoProvider、ssoRefEntryId。编辑标题/备注不会改写这些字段；导入与同步继续接收兼容数据。现有旧方案本轮不动；未来若要求旧方案也停止新增 SSO，应作为独立变更，不借 V2 重构悄悄修改。

## 视觉与动效规范

- 12dp 页面左右留白；字段组间 12–16dp；相邻输入 4dp；同组外侧 24–28dp 圆角、内侧 8dp。复用 Monica 现有配色与动态色，Canvas 中紫色只作示例。
- 字段名 12–14sp，输入值 16sp，展开标题约 32sp；不照搬截图的大号系统字体为默认字号。触控区至少 48dp。所有文案走资源；长译文可换行。
- 单一可折叠顶栏与单一页面转场。新增/移除/重排用局部位置动画；已有输入区不整页 Crossfade。动画建议 160–240ms 起步，低幅度弹性，最终以帧指标选参数。
- 新建页沿用 Monica 独立编辑路由，不照搬截图底部全局导航，避免编辑中误切标签；返回使用统一的未保存草稿确认。保存中防重复提交；校验失败定位首个问题字段，不能只将按钮变灰而不给原因。
- 右下保存按钮始终可达；键盘、底部手势区、错误提示和附件上传区有各自 inset。窄屏/大字体自动纵向堆叠存储位置与账号信息，禁止为了固定高度截断正文。
- 遵循系统关闭动画/减少动态效果；焦点、光标、滚动锚点不随着字体、收藏、OTP 秒数更新而跳动。
- 大屏仅限制正文最大宽度并居中，弹层按窗口调整；不重新引入已撤销的大屏双栏或胶囊导航改造。
- 本轮 Canvas 是可编辑静态状态稿，组件外观与状态已在浏览器实际渲染核查；拖动、键盘、无障碍、原生弹性及数据库保存仍须实现后的 Android 测试，不将设计稿当成功能验证。

## 架构与性能边界（后续实现建议）

新建入口先创建轻量草稿并导航，展示可输入的核心字段。解锁会话提供 SecurityManager、数据库句柄和已有依赖，不在点击路径重复构造。候选列表、图标匹配、附件解析、长密钥校验按需在后台执行；首屏不等待全库读取或网络请求。已验证过的安全管理器复用、单层导航转场必须保留。

建议拆为统一 EditorHost（顶栏/归属/保存/退出）、类型专属编辑组件、会话内 DraftStore、后端能力与保存协调层；名称只表示职责，实施前再确定具体类名。不要写一个覆盖所有类型的超大动态表单解释器。

列表按字段/字段组提供稳定 key 与 contentType，避免“一个 Lazy item 包整个复杂表单”；每行只订阅自己需要的状态。输入即时更新本行，昂贵的强度/格式分析 debounce + 后台 latest-wins，并以草稿版本防止迟到结果覆盖新值。OTP 每秒变化只更新预览行；生成器结果携带字段 ID 与请求版本。

Rust 优先复用已存在的 MDBX/JNI、解析与批量计算边界。新增候选包括大量候选记录的投影/筛选、长密钥/大型 JSON 校验；是否启用必须包含 JNI 编解码与首次加载的实测收益。**不为每个字符跨 JNI，不把 Compose 布局和动画搬到 Rust，也不为了“Rust 化”同时重写已工作密码学实现。** 当前 GPG 生成走 Bouncy Castle，先保持后台运行；若未来迁 Rust，应单独验收算法、口令、指纹、格式互通与取消行为。

敏感草稿会话内存持有，旋转由 ViewModel 延续，不进 Bundle、SavedStateHandle、日志或普通磁盘文件。锁定时清除/隔离敏感状态，重新解锁后按明确产品策略提示重新输入；进程被杀不承诺恢复明文。只有经过独立设计的加密草稿存储才能提供跨进程恢复。附件用引用与流处理，不提前读全文件到首屏。

## 存储兼容是开关上线的前置条件

新旧编辑器共享现有语义模型和已验证的后端适配；V2 只构建“修改了哪些字段”的变更集，不从当前可见组件重新拼一个缺字段对象。折叠、不展示、移除、显式清空分别建模。保存前核对目标能力、会话状态、目标身份与版本。

多库不是跨系统事务。每个“数据库 × 凭据”维护保存状态、原生身份、重试去重标识；明确区分已持久化、待同步、失败和未执行。任一目标失败则保留草稿和成功凭据，只重试失败项，不能全量重建。Bitwarden 本地入队不等于服务器同步完成。附件后续失败不能声称整条未保存或盲目重建主记录。

目标切换后如有不支持字段，显示具体字段和选择：换目标、取消切换、明确移除有关新增内容；对已有不可表示内容应阻止有损覆盖。多目标创建不能把字段截成能力交集后静默丢弃。现有“移除副本目标”的行为必须保持可见且可确认，不借修改 UI 改成删除源条目。

详细矩阵见 [验收方案](verification-plan.md)。所有兼容结论在本轮只是设计要求；未实测的库/字段组合不得标记为已支持。

## 可选开关、回退与推进顺序

设置 → 实验功能 → **新建与编辑页面**：`经典（默认）` / `简洁（测试）`。说明：“使用按需添加字段的新页面，可随时切回；不会转换已保存的数据。”覆盖已验收的类型，不改变数据库格式。

开关仅影响下次打开，正在编辑的草稿不被销毁。使用共同草稿契约前，禁止在有未保存内容时热切换实现；允许用户保存后返回切换。异常页提供“返回 / 重试 / 使用经典页面”，若转移草稿不具备无损保证则明确提示，绝不能无声清空。

每个“类型 × 数据库能力”单独放行。不支持的组合启动经典页并一次性说明，而不是打开简洁页后才失去保存能力。测试版开关不控制加密格式或身份生成；关闭即可退回经典 UI。不要从 V2 自动迁移用户数据库。

推进顺序：

1. 评审 Canvas 的默认字段、分区追加、各类型模板与失败状态，确定设计。
2. 先锁定现有保存契约/兼容测试，补齐逐目标结果和幂等边界；不混入界面改造。
3. 受开关保护实现公共骨架与密码页，再按验证码/Wi-Fi → 卡包/笔记 → SSH/GPG/API/原生 KeePass/Send 分批接入；每批独立验收。
4. 跑新旧往返、故障注入、真实原生布局与无构建负载的性能对照；再考虑符合指标的 Rust 优化。
5. 测试版至少两个反馈周期，未解决的丢字段/重复条目/错误归属为零；各受支持组合通过后，才能另行决定默认切换。现阶段不删除经典页。
